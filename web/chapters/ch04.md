# 4. Reading a function call

A *function* is the tool — `round`, the piece of R that knows how to round
numbers. It sits there whether or not anyone uses it. A *call* is one act of
using it: `round(3.7)` is a call, and `round(3.14159, 2)` is a different
call to the same function.

Most of what you do when reading someone else's R is reading calls. Which
function, what was handed to it, and what was left out.

::: exercise {#ch04-ex01}

## Arguments you didn't supply

Many arguments have a fallback value that the function uses if you say
nothing. These are called *defaults*, and they're invisible in the code —
you can't tell from looking at a call which arguments were left to their
defaults, only which ones weren't.

::: exercise {#ch04-ex02}

To see what a function expects to receive, you'd normally open its *help
page*. In a full R setup, typing `?` followed by the function's name opens
it:

```
?round
```

Help pages don't display properly inside these pages, so for now the
exercises show you the part that matters, and the **Functions** panel at the
top of the page lists every function you've met so far with the same
information. Later in the course you'll be able to look up any function you
like.

The first thing a help page shows is a line called *Usage*.

::: exercise {#ch04-ex03}

## Naming what you pass in

Inside a call, you can attach a value to an argument's name with `=`.

```r
round(x = 3.14159, digits = 2)
```

That `=` is not the same as the `<-` you met in the last module. `<-` stores
a value in a variable that stays around afterwards. `=` inside a call says
*this value is for that argument*, and it applies to this one call only.
Nothing named `digits` exists after the line has run.

Naming changes nothing about the result. `round(3.14159, 2)` and
`round(x = 3.14159, digits = 2)` return exactly the same value. The names
are there for the human who reads your code next — and so that you can
write the arguments in any order you like.

::: exercise {#ch04-ex04}

## When the default isn't what you assumed

A default is somebody else's decision about what you probably wanted. Most
of the time they were right. When they weren't, nothing seems to go wrong —
you get a clean answer to a question you didn't ask.

## What a call gives back

A call doesn't just print something. It *returns* a value, and that value is
ordinary — you can store it in a variable, do arithmetic on it, or hand it
straight to another function.

```r
dose <- round(3.7)
```

Nothing prints here, for the same reason nothing printed in the last module:
storing isn't a question. The rounded value is sitting in `dose`, ready to
use.

::: exercise {#ch04-ex09}

::: exercise {#ch04-ex10}

You will never know every function, and you don't need to. What you need is
to take an unfamiliar call apart far enough to ask a sharper question about
it — which function, what went in, what was named, and what was quietly left
to a default you never saw.

And when you know what you want but not what it's called, describe it — to a
search engine, an AI, or the Functions panel — then check what the function
actually does before you trust it.
