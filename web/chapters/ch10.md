# Reading what you get back

Three modules ago, a data frame was new. Since then you've:

- looked inside one with `str()` and `summary()`
- picked out any rows and columns with `[row, column]`
- watched one missing value invent a patient who didn't exist
- worked out every patient's MAP in a single line

None of that was R for its own sake. Each piece was chosen because you need
it to check code you didn't write — and you've been doing exactly that since
module 2, every time code ran cleanly and gave the wrong answer. From here,
it's the main event.

**Here, we won't practice writing code from scratch. We'll practice reading
generated code and thinking about what to check.**
:::

# 10. Lists, lightly

When R runs a statistical test, you don't get back a single number — you get
a bundle of results. You'll meet a bundle like this whenever generated code
runs a test.

::: exercise {#ch10-ex01}

A *list* is a collection of named pieces, which can be different sizes and
different types. Compare that with what came before. A vector holds one type
of value. A data frame needs every column to be the same length — and since
each column is a vector, each column holds one type too. A list needs
neither of those.
