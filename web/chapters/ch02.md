# 2. Your first R code

Below is a box you can type in. Whatever you put there, R will read and
answer. Try this:

```r
120 + 80
```

Press Run — or press Cmd+Enter, which is quicker and works in every code
box in this course. On Windows it's Ctrl+Enter.

You get `[1] 200`. Ignore the `[1]` for now — it's R's way of numbering its
answer, and it'll make sense in a few modules. The `200` is the part that
matters.

That's the whole loop. You write something, R answers, you look at the
answer. Everything else in this course is a more interesting version of
those three steps.

Every code box on these pages works the same way. You can change what's in
them and run them as often as you like — nothing you type here can break
anything, so experiment freely.

R handles arithmetic the way a calculator does, including the order of
operations:

```r
(120 + 80) / 2
```

::: exercise {#ch02-ex01}

Parentheses work the way you'd expect, and you'll want them more than you
think. R follows the same order of operations you learned in school — which
means a formula typed straight across can quietly compute something you
didn't intend.

## Asking R to do something specific

Arithmetic is built in. Most of what you'll want isn't — it lives in a
*function*, a named piece of work you can ask for in a single line. It's a
bit like `f(x)` in maths: the function has a name, and whatever you want it
to work on goes in the parentheses after it.

To round a number, use `round`. Write the name, then put the number inside
the parentheses.

```r
round(93.333)
```

You get `[1] 93`.

Most functions can be adjusted. `round` accepts a second thing inside the
parentheses — how many decimal places you want — separated from the first by
a comma.

```r
round(93.333, 1)
```

Now you get `93.3`. The things you put inside the parentheses are called
*arguments*, and the order they go in matters.

::: exercise {#ch02-ex05}

R is particular about what it reads. Code only runs if it's punctuated and
structured the way R expects, and that structure is what *syntax* means.

::: exercise {#ch02-ex09}

An error like that is the good case. R stopped before it did anything, so
nothing ran, nothing was stored and nothing was damaged. You read the
message, fix the line, run it again. Errors are loud, and loud problems are
cheap ones — the message tells you roughly where to look.

The expensive problems are quiet.

::: exercise {#ch02-ex06}

## The part this course is actually about

If the syntax is right, your code will run. Code that runs is not
necessarily code that is correct.
