# 3. Variables and types

Sometimes you need the same value more than once. Rather than typing it out
every time, you can store it under a name and use the name instead. That
stored thing is called a *variable*.

In R you create one by writing the name, then `<-`, then the value you want
to keep in it.

```r
dose_mg <- 500
```

The arrow points from the value into the name. Read it as *dose_mg gets
500*.

::: exercise {#ch03-ex01}

Most useful code is more than one line long, and R reads it the way you read
a page: top to bottom, one line at a time. Each line is a complete
instruction, finished before the next one starts. So by the time R reaches
the third line below, the first two have already happened and their values
are waiting to be used.

```r
weight_kg <- 70
height_m <- 1.75
weight_kg / (height_m * height_m)
```

::: exercise {#ch03-ex02}

You can store anything you like in a variable, and you can store something
new in a name you've already used — the old value is replaced with no
warning. R is also exact about the names themselves. It matches what you
typed, character for character, and won't guess at anything close.

::: exercise {#ch03-ex03}

::: exercise {#ch03-ex04}

## Not everything is a number

Every value so far has been a number. R calls that type *numeric*.

Text is a different type, and you mark it with quotes. R calls it
*character*. If you've programmed before you may know it as a string — same
idea, different word.

```r
site <- "north"
```

The quotes are what make it text. A number in quotes is text too, even
though it looks like a number, and that turns out to matter more than you'd
expect.

## A third kind of value

Numbers and text are easy to accept as data. The third type is less
obvious.

When you ask R a question with a yes-or-no answer — is this bigger than
that, are these the same — what comes back isn't a number or text. It's
`TRUE` or `FALSE`. R calls this type *logical*; elsewhere you'll see it
called a boolean.

```r
sbp <- 118
sbp > 140
```

This looks like a small thing and isn't. Later, when you have a column of a
thousand blood pressures, asking which ones are over 140 gives you a
thousand TRUEs and FALSEs — and that is how filtering a dataset actually
works underneath.

## When the type is wrong

::: exercise {#ch03-ex10}

When arithmetic fails and you can't see why, `class()` is the first thing to
reach for. It tells you what R thinks a value is, which is often not what
you assumed — most often a number that arrived as text and has been text
ever since.

You've now met both ways code can go wrong. One kind stops and prints a
message pointing at the problem. The other runs, returns a number, and says
nothing at all. The first is inconvenient. The second is the one worth
building habits around.
