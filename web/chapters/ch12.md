# 12. Packages and the tidyverse

A *package* is a bundle of functions someone else wrote that isn't already
in R. Packages let you do more with fewer lines. Using one takes two steps,
and they're easily confused:

1. Install it — once per computer.
2. Load it with `library()` — in every session.

## When two packages share a name

Sometimes loading a package prints a message saying some functions are
"masked". It's not an error. It means two packages have a function with the
same name, and R is telling you which one it will now use. It's worth
reading, because it explains one of the most misleading errors you'll meet.

## The tidyverse

The *tidyverse* is a family of packages built to work together, dplyr among
them, and most generated R is written with it. It uses two conventions that
are different from what you've learned so far:

- **Column names on their own.** Inside tidyverse functions like `filter()`,
  you give the data frame first, then refer to its columns by name alone. So
  `filter(patients, sbp > 140)` does what `patients[patients$sbp > 140, ]`
  does — no `patients$` needed, because `filter()` already knows which data
  frame to look in.
- **Missing values are dropped, not invented.** `filter()` leaves out rows
  where the answer is `NA`, instead of adding a row of `NA`s the way square
  brackets did in module 8.

In other words, when a package brings in new functions, it can bring new
conventions with them.

## Meeting something new

Most of what you'll meet in real code won't be in this course. That's
expected — the skill is knowing what to do about it.

::: exercise {#ch12-ex13}

That's the end of Part C. Reading code you didn't write comes down to a few
questions:

- Are the right packages loaded?
- Which function actually ran?
- What does each step hand to the next?

And when you meet something you don't recognise: name it, try it on
something small where you already know the answer, and check what it did
against what the code needed.
