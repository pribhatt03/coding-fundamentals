# 5. Vectors

Real data never comes as one number. It's a shift's worth of blood
pressures, a column of lab values. When you want to keep many values
together under one name, you use a *vector*.

You make a vector with the `c()` function — short for *combine*. It puts
several values into one vector, which you can store in a variable like
anything else:

```r
sbp <- c(118, 142, 131, 156)
```

A vector holds several values, in order, and they all have to be the same
kind: all numeric, all character, or all logical.

::: exercise {#ch05-ex01}

## Picking out one value

To pick out one value from a vector, put its position in square brackets.
Positions are numbered in order, and R starts counting at 1 — so `sbp[1]` is
the first value. Most other programming languages start at 0, which is worth
remembering if you ever read Python.

::: exercise {#ch05-ex02}

## When one value spoils the rest

A vector has to be one type all the way through, and R makes sure of it. If
even one value you put into `c()` is text, R turns every value into text to
match.

This matters in real life. A single entry like `"<0.5"` or `"hemolysed"` in a
column of lab values is enough to turn the whole column into text.

::: exercise {#ch05-ex07}

That becomes a problem as soon as you use a function on the vector. Most
functions only accept certain kinds of value — `mean()`, for example, needs
numbers. Hand it the wrong kind and it either stops with an error, or
quietly gives you something you didn't want.

FALSE. Give them a list of TRUEs and FALSEs, and R keeps only the values that
