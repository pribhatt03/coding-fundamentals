# Working with AI

This is the part the course is built for. Everything so far has been the
fundamentals of coding: what R does, how to read it, and how it breaks.
Here, you'll use those fundamentals to work with AI — asking it well for
code, protecting your data, managing long sessions, and checking that the
results are right.

**From here on, an AI can write most of the code. Your job is everything
around it.**
:::

# 15. Asking well

You can ask an AI to write code for you — but to do it well, you need to
give it the details the task depends on, and no more. An AI can't see your
data, and sharing it usually isn't safe when it's patient data or work you
don't want scooped. It can't read your mind either. Everything you don't tell
it, it guesses, and code built on a wrong guess usually runs without
complaint.

You won't know everything up front. Often you find out what to tell it by
running its code and checking the result — and that's part of the process.

::: exercise {#ch15-ex01}

::: exercise {#ch15-ex02}

## Enough, and no more

Strike a balance. Tell the AI everything that changes the code — names
(placeholders are fine), types, quirks, clinical decisions — and nothing
that doesn't: the study's aim, the real values, where the data came from.
The less you share, the less can leak, about patients or about an
unpublished idea. Placeholder names protect an idea too, but you're then
showing a different example, so map the names back carefully when the code
returns.

A simple example is often the clearest way to show what you mean: describe
a small dataset shaped like yours. When you simplify, ask: is it still
representative? Does it still have the missing value, the odd entry, the
boundary case?

::: exercise {#ch15-ex10}

## Have and want

Two things go in your prompt:

- **Have** — what the data looks like.
- **Want** — your specific ask, including any decisions only you can make.

A want might be: clean the data and create a new variable; make a particular
visualisation; edit a plot so it better shows what you're trying to
highlight; make a figure fit a journal's style guidelines.

::: exercise {#ch15-ex03}

## The check is yours

An AI can be confidently wrong, or do something slightly different from
what you asked. A quick spot-check catches a lot: do the counts add up to
the total? Does one patient you know land where they should? Is the number
plausible? A check like this is a small fraction of the work — you're not
doing the task again, just looking for signs it went wrong.

Work it out however suits you: pen and paper, or a few throwaway lines in
the *console* — the place where you type a line of R and see its answer
straight away, without keeping it. The code boxes in this course work the
same way. Ideally, do it before you see the AI's result, so it can't nudge
you either way. Printing things to check is fine, whether the AI writes the
line or you type it yourself: R computes it. The AI telling you it did what
you asked is not a check.

::: exercise {#ch15-ex09}

## It's a loop

It's a loop: ask, run the code, check it, find what's wrong, and tell the AI
what you found. Looking first with `str()` or `summary()` catches a lot, but
some things only turn up once you check — that's normal, not a failure.
"It's wrong, fix it" gives the AI nothing to go on. Say what you found, and
what you've decided.

::: exercise {#ch15-ex11}

## After the code arrives

If something doesn't look right, ask the AI what it assumed — as a place to
start looking, not a guarantee. And when its code uses something you don't
recognise: name it, look it up, try it on something small, and check what
it did.

::: exercise {#ch15-ex04}

::: exercise {#ch15-ex05}

## How much to ask for at once

You can build your code incrementally: build a little, check a little. How
much you ask for and how often you check are separate choices. Breaking a
task into steps makes each one small enough to check, and often small
enough to write yourself. Save the AI for what you can't write — for a
simple step, writing it yourself is often quicker.

If you've forgotten how to do a small step, it's fine to ask an AI to remind
you, then write it yourself. Each time you do, it sticks a little better.
