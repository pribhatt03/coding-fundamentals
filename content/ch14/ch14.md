# 14. Errors that don't stop you

The more dangerous way code goes wrong is when R doesn't send you an error at
all — so there's nothing to paste into an AI. In this module, we'll work
through one case: a lab summary that comes out wrong, where R never said a
word.

In practice, a lot of checking happens in quick lines you run and then throw
away: look at the first few rows, count something by hand, work a value out a
second way. They don't belong in your final script, but they're how you know
the script works. The code boxes in this course work exactly like that, and
in module 18 you'll do the same in RStudio's console.

That's the end of Part D. Three habits — look at the structure, look at the
spread, and check results against something you know. None of them needs an
error message. Next, we'll work with AI on purpose.
